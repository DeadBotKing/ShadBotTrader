## ۳. 🎯 ریشهٔ اصلی — باگ ۵۳ ساختاری: «SL چسبیده به entry»

براکت از رنجِ **کل فردا** ساخته می‌شود:
- TP = predicted_high → از entry به‌طور میانگین **$45 دور**
- SL = predicted_low − spread → از entry به‌طور میانگین فقط **$8** (median $5.6، min **$0.07**!)

چون entry اغلب **داخل/نزدیک رنج دیروز** است، predicted_low تقریباً روی خود
entry می‌افتد → SL با کوچک‌ترین نویز 5M فعال می‌شود:
- **۵۳ ترید در همان کندلِ ورود SL خوردند** (WR آن‌ها: ۰٪!)
- فقط **۱۶٪** تریدها اصلاً به TP دور رسیدند
- نسبت ظاهری R/R = ۱۰-۳۰x (فریبنده — گیت ۱.۲x را راحت عبور می‌کند)

## فاز ۷۵ — بازسازی براکت حول entry (درخواست اپراتور)

**درخواست:** معاملاتی که براکت‌شان وارونه می‌شود (SL سمت اشتباه entry)
**رد نشوند** — باز شوند با براکتی که entry بین TP و SL باشد و SL سمت
ضرر باشد، با در نظر گرفتن بازهٔ حد سود/ضرر مدل.

### پیاده‌سازی (`bracket.from_model_levels`)

گیتِ rejectِ باگ ۵۲ حذف شد؛ جای آن:

```text
width = predicted_high − predicted_low      (عرض رنج پیش‌بینی مدل)
BUY : SL = entry − width · TP = entry + mult × width
SELL: SL = entry + width · TP = entry − mult × width
(mult = reward_risk_multiplier؛ بدون آن = 1.0)
```

- براکتِ سالم (entry داخل باند): رفتار قبلی، دست‌نخورده
- براکت وارونه: پرچم `recentered=True` در metadata (برای CSV/ریپلی)
- رنجِ عرض‌صفر هنوز رد می‌شود (قابل اندازه‌گیری نیست)

### تفسیر معاملاتی

این یعنی: مدل رنج می‌گوید «فردا این‌قدر نوسان دارد». اگر قیمت امروز
بیرون آن باند است، به‌جای دورریختن سیگنال، همان نوسان‌سنجی را حول
قیمت فعلی اعمال می‌کنیم — SL یک عرضِ رنج زیر entry، TP با نسبت R/R
انتخابی بالای آن.
