# چرا مدل رنج همیشه یک درصد ثابت پیش‌بینی می‌کند؟ — ریشه‌یابی کامل

**یافته:** برای هر کندلی که انتخاب می‌کنی، مدل رنج تقریباً همان اعداد را
می‌دهد (+0.06% / −0.05% برای 1H · +0.62% / −0.60% برای 1D). این باگ نیست
— محدودیت ساختاریِ معماری فعلی است.

---

## چرا این اتفاق می‌افتد؟

### ورودی مدل:
هر پنجره ۱۵۰×۱۸۲ minmax می‌شود (هر ستون به [-2,+2] فشرده می‌شود).
بعد از این فشرده‌سازی، مدل **نمی‌داند** قیمت الان $2000 است یا $4000.
فقط «شکل» حرکت را می‌بیند، نه سطح قیمت را.

### خروجی مدل:
offset درصدی (مثلاً +0.06%). چون ورودی فاقد اطلاعات مقیاس است،
مدل برای هر ورودی تقریباً یکسان خروجی می‌دهد.

### تشبیه:
مثل این است که به کسی فقط نمودار %R بدهی و بپرسی «قیمت چقدره؟»
او فقط می‌تواند بگوید «در وسط بازه» — نمی‌داند $4000 است یا $2000.

---

## چرا این در بکتست اثر فاجعه‌بار دارد؟

باند پیش‌بینی همیشه ±0.06% است. ولی:
- سیگنال actionable یعنی قیمت ۰.۶٪ حرکت کرده
- پس entry **خارج یا روی مرزِ** باند ±0.06% است
- براکت یا وارونه می‌شود یا SL چسبیده → ترید بی‌کیفیت

## 🛠️ راه‌حل: مدل باید «مقیاس» را بفهمد

دو تغییر لازم است:

### ۱. فیچرهای نسبت قیمت (انجام شد — فاز ۹۴)
```
close_div_sma_20 = close / SMA(20)   → مثلاً 1.05 = ۵٪ بالاتر از روند
close_div_sma_50 = close / SMA(50)
```
این‌ها scale-invariant هستند ولی مدل را از «فقط شکل» به «موقعیت نسبت
به روند» می‌برند. بدون این، مدل عمی‌بود.

### ۲. target را نسبت به **نوسان واقعی** نرمال کن (قدم بعدی)
به‌جای offset درصدی خام، target را بر ATR تقسیم کن:
```
target = (high[t+1] − close[t]) / ATR_14[t]
```
این به مدل می‌گوید «چند ATR بالاتر» — مستقل از سطح قیمت و مستقل از
نوسان روز. وقتی مدل این را یاد بگیرد، خروجی‌ها متنوع می‌شوند چون
ATR از کندلی به کندل دیگر فرق می‌کند.
