## ۱. ریشه‌یابی — باگ نبود، فرمولِ گرسنه بود

فرمول در `DualModelService.build_trainer` (و آینهٔ آن در `run_dual_models.py`):

```python
val_size = max(4, min(2000, rows // 50))   # قدیمی — ۲٪ استخر لیبل
```

`rows` = تعداد نمونه‌های **لیبل‌دار** (نه همهٔ پنجره‌ها). نتیجه روی دیتای واقعی:

| اجرای کاربر | استخر لیبل | val قدیمی (۲٪) | val جدید (۱۰٪) |
|---|---|---|---|
| train-ratio 80% | ~7,000 | **140** | **~700** |
| train-ratio 70% (threshold 0.6%) | 6,150 | **123** | **615** |
| train-ratio 20% (threshold 0.4%) | ~1,745 | **34** | **~174** |

**چرا val با train-ratio coupling داشت؟** چون `train-ratio` پیشوند آموزش را
کوچک می‌کند → استخر لیبل کوچک می‌شود → ۲٪ آن هم کوچک‌تر. پس هر دو مشاهدهٔ
کاربر از یک ریشه بود: **val نسبت ثابتی از یک استخرِ خودش کوچک بود.**

**چرا خطرناک بود؟** گیتِ انتخاب بهترین مدل (فاز ۴۷) بر اساس val_loss روی همین
چند نمونه تصمیم می‌گرفت. با val=34، هر یک نمونه = ۲.۹٪ تغییر val_acc — یعنی
نویز می‌توانست epoch اشتباه را به‌عنوان بهترین ذخیره کند. ضمناً val_acc روی
n=34 از نظر آماری بی‌معناست.

## ۲. تغییرات

### `src/ShadBotTrader/application/services/dual_model_service.py`
1. فرمول پیش‌فرض: `rows // 50` → **`rows // 10`** (کف ۴، سقف 2000 مثل قبل).
2. **گارد ایمنی جدید:** ولیدیشن هرگز فضای اولین fold را نمی‌خورد:
   `val_size = max(4, min(val_size, rows - min_train_size - purge - 4))`
   — رفتار قدیمی سری‌های خیلی کوچک دمو را حفظ می‌کند (بدون این گارد، val بزرگ
   روی دادهٔ کوچک = صفر fold).
3. `train()` حالا پارامتر `val_size: int = 0` می‌پذیرد و به `build_trainer`
   پاس می‌دهد (0 = auto).

### `scripts/run_dual_models.py`
1. آپشن جدید **`--val-size N`** — تعداد مطلق نمونهٔ ولید در هر fold.
2. آپشن جدید **`--val-ratio F`** — کسری از استخر (مثلاً 0.2 = ۲۰٪)؛
   با `--val-size` بازنویسی می‌شود.
3. خط چاپ جدید در سربرگ تا کمبود ولیدیشن دیگر پنهان نماند:
   ```
   val fold size  : 174 samples per fold (10.0% of 1745 labelled windows)
   ```
4. تابع آینهٔ `signal_label_split_balance` همان فرمول + گارد + override را
   اعمال می‌کند (عدد چاپ‌شده = هندسهٔ واقعی آموزش).

### `tests/unit/ai/test_validation_geometry.py` (جدید — ۴ تست)
- پیش‌فرض = ۱۰٪ استخر ✅
- `val_size` صریح بدون تغییر عبور می‌کند ✅
- گارد روی سری کوچک (wave 70 کندلی) اولین fold را زنده نگه می‌دارد ✅
- `service.train` امضای `val_size` دارد ✅

## ضمیمه — «Validation samples per fold» به زبان ساده (برای مرور بعدی)

**تشبیه:** آموزش مثل درس‌خوندنه؛ validation مثل برگهٔ امتحانیه که مدل **هر
epoch** روش امتحان میده ولی هیچ‌وقت از روش یاد نمی‌گیره. «Validation samples
per fold» = تعداد سؤال‌های این برگه در هر دور (fold).

**چرا تکلیفش مهمه:** همین نمرهٔ امتحان (val_loss) تصمیم می‌گیره کدوم epoch
«بهترین»ه و ذخیره بشه (گیت فاز ۴۷). امتحانِ ۳۴ سؤالی = نمرهٔ شانسی = ممکنه
epoch اشتباه ذخیره بشه. امتحانِ ۷۰۲ سؤالی = نمرهٔ قابل‌استناد.

**اعداد روی دیتای واقعی خودمان (50k کندل، train 80%):**
```
40,000 کندل prefix → 7,024 پنجرهٔ لیبل‌دار
val قدیمی (۲٪)   → 140 نمونه  ← خود کاربر کشف کرد و گفت «اشتباه داری»
val جدید  (۱۰٪)  → 702 نمونه  ← خط لاگ: «val fold size : 702 (10.0% of 7024)»
```

**قاعدهٔ استفاده در GUI/CLI:** 0 = خودکار (۱۰٪ استخر لیبل، با گاردِ
«اولین fold جا شود»). عدد دستی فقط وقتی که بخواهیم عمداً قضاوتِ سخت‌گیرانه‌تر
(عدد بزرگ‌تر، دادهٔ آموزش کمتر) یا برعکس داشته باشیم.
