## ۱. سرنخ: دو عدد در تناقض

لاگ آموزش `gold_range_1d v1` هم‌زمان دو چیز گفت:
- `val_mae 0.000081 ~ ±0.16$` ← پیش‌بینی high/low فردای طلا با خطای ۱۶ سنت؟!
- `val_high_mae 0.0024 (≈$4.6) · val_low_mae 0.0058 (≈$11.1)` با **bias ≡ ±MAE**

«۱۶ سنت خطا برای رنج روزانهٔ طلا» ادعایی غیرعادی است (دامنهٔ واقعی روزانه ~۲۰-۴۰$)؛
و این‌که bias دقیقاً برابر MAE باشد یعنی **هر ۴۴۸ خطا هم‌علامت‌اند** —
امضای خروجی near-constant (collapse).

## ۲. ریشه (ردیابی کد — هر دو باگ تأیید شد)

### باگ ۴۷ (اصلی): `WindowedSample.target_index` معنای اشتباه
`WavenetTrainer._build_seq2seq_targets` آن را **اندیس سطرِ پایان پنجره در
series** می‌خواند تا y=[batch,150,2] بسازد. ولی هر سه سازنده (make_windows ·
build_samples_at · make_multi_target_windows) آن را با **شمارهٔ ستون target**
(=182) پر می‌کردند:

```python
end_idx = 182  ← همیشه!
start_idx = 182-150+1 = 33
y[b, k, :] = series[33+k]  ← برای «همهٔ» ۴٬۳۳۱ نمونه یکسان!
```

یعنی برچسب آموزشی رنج از فاز ۵۵ تا امروز **برچسب‌های ثابتِ سطرهای ۳۳..۱۸۲
(داده‌های قدیمی ~۱۹۸۸)** بود، نه برچسب هر نمونه. نتیجه: collapse عمدی و
metric جعلی نزدیک صفر — و توضیح val_maeهای تاریخی غیرقابل‌باور
(0.000010 در گزارش فاز ۵۷!). مدل‌های range قبلی (v1-v3) همگی با این y خراب
آموزش دیده بودند — به همین دلیل بکتست رنج عملاً هرگز معنا نداشت.

مسیر signal آسیب ندید: classification از `sample.target` (مقدار مستقیم)
استفاده می‌کند نه target_index — برای همین دقت‌های سیگنال معتبرند ✅

### باگ ۴۸ (ثانویه): تشخیص per-bound غلط برای seq2seq
`_range_validation_metrics` با `actual[:count, :2]` برای خروجی سه‌بعدی
seq2seq «timestepهای ۰ و ۱» را می‌گرفت (موقعیت‌هایی با تقریباً صفر کانتکست
و خروجی near-constant) نه «ستون‌های high/low آخرین timestep» که نیت بود.

## ۳. رفع

1. هر سه سازنده: `target_index=end` (سطر پایان پنجره) + docstring فیلد.
2. `_range_validation_metrics`: شاخهٔ ndim==3 → مقایسهٔ آخرین timestep.
3. تمیزکاری lint قدیمی trainer (F841/B023/E501×2).
4. ۴ تست رگرسیون: `tests/unit/ai/test_seq2seq_target_alignment.py` —
   target_index = سطر خود نمونه، y دو نمونه مجاور متمایز، قرارداد در
   هر سه سازنده.
