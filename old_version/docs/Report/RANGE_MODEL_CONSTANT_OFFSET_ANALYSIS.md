# آنالیز — چرا مدل رنج برای همهٔ کندل‌ها یک درصد ثابت پیش‌بینی می‌کند؟

**ورودی:** خروجی /data برای رنج 1H-h12 و 1D-h1 — همیشه ~±0.06% / ±0.60%

---

## ۱. تشخیص — مشکل از طراحی مدل است نه باگ کد

مدل رنج:
- **ورودی:** ۱۵۰ کندل × minmax-scaled (هر ستون به [-2,+2])
- **خروجی:** high_offset و low_offset به‌صورت **درصد نسبی** (0.06% یا 0.60%)

**مشکل:** وقتی همهٔ فیچرها minmax می‌شوند، هر پنجره به یک الگوی «شکل مشابه»
تبدیل می‌شود. مدل عملاً نمی‌تواند بداند قیمت الان 2000 است یا 4000 —
همه‌اش در بازهٔ [-2,+2] است. پس خروجی‌اش هم برای هر ورودی تقریباً یکسان است.

این یک محدودیت ساختاری است، نه یک باگ قابل‌فیکس با یک خط کد.

## ۲. سه راه‌حل (به ترتیب اثر)

### راه ۱ — بهینه‌ترین: unscaled close به‌عنوان فیچر اضافه

```python
# در build_feature_matrix، یک ستون اضافه کن:
# close[t] / ATR_50[t]  یا  close[t] / close[t-100]
```
این به مدل می‌گوید قیمت الان نسبت به میانگین کجاست — بدون minmax شدن.

### راه ۲ — آموزش با absolute price target

به‌جای offset درصدی، مستقیم absolute high/low دلاری آموزش بده.
مدل یاد می‌گیرد قیمت واقعی کجاست. (نیاز به تغییر target builder)

### راه ۳ — بگذار همین باشد (ساده‌ترین)

درصد ثابت = باند ±$25 روی طلا $4000. این واقعاً بد نیست به‌عنوان
«حدودِ نوسان روزانه». مشکل فقط این است که برای هر کندل یکسان است.
اگر استراتژی فقط «باند حدودی» می‌خواهد، همین کافی است.

## ۳. 📋 توصیهٔ عملی

**راه ۱ را پیاده کن** — یک فیچر اضافه کن که نسبت قیمت به میانگین بلندمدت
را نشان دهد. این مدل را از «پیش‌بینی ثابت» نجات می‌دهد بدون تغییر معماری.

**تا آن زمان:** با همین مدل پیش برو — باند ±$25 حدودی است ولی بهتر از
هیچ است. بکتست با R/R=1.2 + session filter + min SL=$10 اجرا کن.
