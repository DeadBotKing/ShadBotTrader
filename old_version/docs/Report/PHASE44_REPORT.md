# فاز ۴۴ — ۵٬۹۸۶ قدم برای یک epoch، و ۱۱ دقیقه سکوت

**تاریخ:** 2026-08-18
**وضعیت:** ✅ کامل — Quality Gate سبز

---

## خبر خوب اول

لاگ تو نشان می‌دهد **کرش فاز ۴۳ رفع شده و آموزش واقعاً شروع شده**:

```
fold   1/1 | train[0:47886] (47886 samples) -> val[47886:48883] (997 samples)
    [--------------------]   0.0% | batch 1/5,986 | loss 1.5662 | mae 0.0550
```

استریم کار می‌کند، رم منفجر نمی‌شود، خط پیشرفت با loss و mae می‌آید.

## ولی همین یک خط دو مشکل را لو می‌دهد

### باگ ۳۷ — `batch_size = 8` روی ۴۷٬۸۸۶ پنجره

عدد ۸ برای سری دموی چندصد سطری انتخاب شده بود. روی دیتای واقعی:

```
47,886 ÷ 8  = 5,986 قدم گرادیان برای یک epoch
```

هر قدم یک forward+backward کامل روی ورودی ۵۰۰×۱۲۳ است.

**رفع:** اندازهٔ batch با حجم دیتا مقیاس می‌گیرد، مثل کاری که فاز ۳۹ با
foldها کرد:

| سطرها | batch_size | قدم در هر epoch |
|---|---|---|
| ≥ ۲۰٬۰۰۰ | ۶۴ | **۷۴۸** (قبلاً ۵٬۹۸۶) |
| ≥ ۵٬۰۰۰ | ۳۲ | |
| ≥ ۱٬۰۰۰ | ۱۶ | ۱۲۹ (قبلاً ۲۵۸) |
| کمتر | ۸ | بدون تغییر |

**۸ برابر قدم کمتر.**

### باگ ۳۸ — ۱۱ دقیقه سکوت بین دو خط

با ۸ خط در هر epoch و ۵٬۹۸۶ batch، فاصلهٔ خطوط ۷۴۸ batch بود ≈ **۱۱ دقیقه**.
یازده دقیقه سکوت دقیقاً همان چیزی است که «هنگ کرده» خوانده می‌شود — همان
شکایتی که این گزارشگر برای رفعش ساخته شد.

**رفع:** یک کف زمانی. هر **۳۰ ثانیه** حداقل یک خط چاپ می‌شود، فارغ از
اینکه چند batch گذشته باشد.

### به‌علاوه: ETA

```
[###-----------------]  12.6% | batch 94/748 | loss 0.8070 | eta 4s
[#####---------------]  25.0% | batch 187/748 | loss 0.7140 | eta 3s
```

بدون ETA، «batch 1/5,986» هیچ نمی‌گوید که باید منتظر بمانی یا اجرا را
قطع کنی و پنجرهٔ کوچک‌تر بزنی. روی batch اول ETA چاپ نمی‌شود چون هنوز
چیزی برای برون‌یابی نیست.

## یک نکتهٔ صادقانه دربارهٔ سرعت

در سندباکس اندازه گرفتم:

```
batch_size=8  : 594 batch، 511 ثانیه
batch_size=64 : 297 batch، 542 ثانیه   ← تقریباً یکسان!
```

**CPU این سندباکس AVX2/FMA ندارد**، پس batch بزرگ‌تر بردار‌سازی نمی‌شود و
سودی نمی‌دهد. ولی لاگ خودت می‌گوید CPU تو **دارد**:

```
This TensorFlow binary is optimized to use available CPU instructions...
To enable the following instructions: SSE3 SSE4.1 SSE4.2 AVX AVX2 FMA
```

روی سخت‌افزار تو batch ۶۴تایی معمولاً ۳ تا ۶ برابر سریع‌تر است. **ولی این
را اندازه نگرفته‌ام و نمی‌توانم تضمینش کنم.**

آنچه مستقل از CPU قطعی است:
- قدم‌های گرادیان: **۵٬۹۸۶ → ۷۴۸**
- خطوط پیشرفت: **۸ → ۲۰** در هر epoch
- حداکثر سکوت: **۱۱ دقیقه → ۳۰ ثانیه**

## بدهی صریح

- **سود سرعت روی سخت‌افزار تو اندازه‌گیری نشده.** در سندباکس صفر بود چون
  CPU بردارساز ندارد. اگر روی ویندوز هم تفاوتی ندیدی، بگو تا سراغ
  علت‌های دیگر بروم (مثلاً عمق شبکه یا نرخ خواندن دیتاست).
- هشدار `shuffle=True was passed, but will be ignored` هنوز هست. بی‌ضرر
  است — دیتای سری‌زمانی نباید shuffle شود — ولی نویز لاگ است.
