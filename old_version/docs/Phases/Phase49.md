## ۱. مشکلی که وجود داشت

در فاز ۴۸ ارزیاب مدل (`ModelEvaluationService`) لیبل‌های BUY/SELL/HOLD را
دوباره می‌ساخت تا دقت را حساب کند — ولی با یک عدد **ثابت**:

```python
threshold = 0.0008        # همیشه، مهم نیست مدل با چی آموزش دیده
```

یعنی مدلی که با آستانهٔ ۰.۲۵٪ آموزش دیده بود، با **کلید سؤالِ ۰.۰۸٪**
تصحیح می‌شد. روی دیتای واقعی ۵ دقیقه‌ای خودت این تفاوت کوچک نیست:

| آستانه | BUY | SELL | HOLD |
|---|---|---|---|
| ۰.۰۸٪ | ۲۹.۹٪ | ۲۸.۷٪ | ۴۱.۴٪ |
| ۰.۲۵٪ | ۸.۶٪ | ۸.۴٪ | **۸۳.۰٪** |

مدلی که یاد گرفته بود ۸۳٪ مواقع بگوید HOLD، با کلیدی نمره می‌خورد که فقط
۴۱٪ آن HOLD بود. نتیجه: **دقت کمتر از واقعیت گزارش می‌شد** و تو به مدلی
که سالم بود می‌گفتی خراب است.

## ۲. چه چیزی عوض شد

### الف) رکورد مدل حالا قانون لیبل را حمل می‌کند

`ModelRecord` دو فیلد گرفت:

```python
threshold: float = 0.0   # نوار خنثی، به‌صورت کسر (0.0025 == 0.25%)
horizon:   int   = 0     # چند کندل جلوتر را نگاه می‌کند
```

`0.0` یعنی «ثبت نشده» — هم مدل‌های قبل از فاز ۴۹، هم همهٔ مدل‌های range
که آستانه برایشان بی‌معناست.

روی دیسک (`v1_training.json`) تأییدشده:

```json
{
  "model_id": "gold_signal_1h",
  "role": "signal",
  "epochs": 1,
  "folds": 1,
  "threshold": 0.0025,
  "horizon": 5,
  ...
}
```

### ب) آموزش در **هر دو** مسیر ذخیره می‌نویسدش

نه فقط ذخیرهٔ نهایی. چک‌پوینتِ هر epoch (فاز ۴۶) هم رکورد می‌نویسد، و
اگر فقط یکی از این دو را وصل می‌کردیم، هر اجرایی که بهترین epoch‌اش
آخری نبود آستانه‌اش را گم می‌کرد. یک تست مستقیماً هر دو محل را می‌شمارد.

### ج) ارزیابی آستانهٔ خودِ مدل را می‌خواند

```
labels   : neutral band 0.2500%, horizon 5 candle(s) — taken from the model's training record
```

و برای مدل قدیمی که آستانه ندارد، دروغ نمی‌گوید:

```
labels   : neutral band 0.0800%, horizon 5 candle(s) — ASSUMED, the model has no recorded threshold
```

عدد فرض‌شده **اعلام** می‌شود، پنهان نمی‌شود.

### د) «Retrain a saved model» دیگر آستانه را پاک نمی‌کند

فیلد `Signal threshold %` در فرم Retrain حالا **خالی** است:

```
Signal threshold %  [        ]
  ↳ leave empty to keep the threshold this model was trained with
```

قبلاً `0.08` از پیش پر بود؛ هر بار که Retrain را بدون دست‌زدن به آن فیلد
می‌زدی، یک مدل ۰.۲۵٪ بی‌سروصدا تبدیل به مدل ۰.۰۸٪ می‌شد. حالا خالی یعنی
«همان چیزی که داشت»، و اگر عددی بنویسی همان برنده است.

## ۳. اثبات‌ها (نه ادعا)

فایل جدید: `tests/integration/test_threshold_recorded.py` — ۱۷ تست.

| چه چیزی ثابت می‌شود | چطور |
|---|---|
| رکورد آستانه را می‌نویسد و می‌خواند | write → read روی دیسک |
| JSON روی دیسک عدد را دارد | خواندن مستقیم فایل |
| رکورد قبل از فاز ۴۹ کرش نمی‌کند | JSON بدون فیلد → `0.0` |
| هیچ آستانهٔ hard-code‌ای در `_score_signal` نمانده | با `ast` سورس تابع اسکن می‌شود |
| دو آستانه = دو کلید سؤال = دو دقت | جدول لیبل واقعی |
| مدل با آستانه، با نوار خودش نمره می‌گیرد | مدل Keras واقعی آموزش و ارزیابی می‌شود |
| مدل بدون آستانه می‌گوید «ASSUMED» | همان مسیر، بدون رکورد |
| Retrain با فیلد خالی ۰.۲۵٪ را نگه می‌دارد | argv اسکریپت بازرسی می‌شود |
| Retrain با عدد صریح همان عدد را می‌فرستد | `0.4` → `0.004` |

تستِ `ast` عمدی است: اگر روزی کسی دوباره `threshold = 0.0008` را داخل
تابع بنویسد، تست قرمز می‌شود — نه اینکه سال بعد کشف شود.

یک باگ جانبی هم همین‌جا گرفته شد: استابِ `Role` در
`test_best_model_kept.py` فیلد `target` نداشت، پس چک‌پوینت با
`AttributeError` می‌افتاد. استاب هم‌راستا شد.

  آموزش ببینند.

- **early stopping هنوز نیست** — ۲۰ epoch کامل اجرا می‌شود حتی اگر از
  epoch پنجم بدتر شود. بهترین مدل نگه داشته می‌شود ولی زمان هدر می‌رود.
